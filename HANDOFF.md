# Core Coach: передача проекта

Состояние исходников: **0.9.7**, 15 октября 2026 года. Локальная рабочая папка автора — `D:\wk-coach`. На другом компьютере проект можно клонировать в любую обычную папку.

## Что это за приложение

Core Coach — Electron-приложение для Windows с отдельным оверлеем пика и боковым оверлеем советов во время матча. Основная цель пикера: выбрать героя на указанной позиции и рейтинге против известных врагов с учётом союзников и базового WR. Приоритет пользователя — обоснованное качество рекомендаций, простой интерфейс и небольшая нагрузка на игру.

В текущем каталоге пикера **127 героев**, позиции **1–5**, до **пяти рекомендаций**. Выбранные и забаненные герои исключаются. Личных предпочтений, бонусов за комфорт и ручных бонусов за «баланс драфта» нет. Карточка показывает WR на позиции, понятную причину выбора и риск. Внутренний индекс служит сортировке, а не прогнозу процента побед; сортировка выполняется по полной точности.

Подробные игровые советы, предметы и навыки реализованы для пяти carry-профилей: Wraith King, Juggernaut, Sven, Phantom Assassin и Luna. **Каталог из 127 героев в пикере не означает 127 полноценных игровых профилей.**

Приложение получает собственные показатели через Dota GSI, распознаёт видимые портреты и значки, позволяет вручную исправить состав и участников линии. Оно не знает скрытые позиции, предметы всех врагов или полное состояние драки. Ручной выбор напарника и двух врагов доступен в основном окне и боковом оверлее.

## Запуск из чистого клона

Нужны Windows и **Node.js 22.12.0 или новее**: это минимальное требование зафиксированного Electron **44.7.0**. Единственный lockfile проекта сейчас — `pnpm-lock.yaml` формата 9. Используй совместимый pnpm и установку из него; не создавай второй lockfile без отдельной причины.

```powershell
Set-Location -LiteralPath 'D:\wk-coach'
pnpm install --frozen-lockfile
```

Если менеджер пакетов пропустил установочный скрипт Electron и файла `node_modules/electron/dist/electron.exe` нет:

```powershell
node node_modules/electron/install.js
```

Запуск исходников:

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
& .\node_modules\electron\dist\electron.exe .
```

Переменная `ELECTRON_RUN_AS_NODE` при обычном GUI-запуске должна отсутствовать. Это удаление относится только к текущей оболочке. Также доступен `pnpm start`. `Start-Coach.cmd` предпочитает уже существующую portable-сборку, поэтому при разработке запускай Electron явно, чтобы случайно не проверить старую сборку.

`Setup-Coach.ps1` — прежний установщик: он использует `npm install` и сразу обновляет данные по сети. Для воспроизводимой передачи исходников выше приведена установка из имеющегося lockfile без обязательного обновления данных.

Для проверки настоящего матча установи GSI из настроек приложения, добавь `-gamestateintegration` к существующим параметрам запуска Dota и перезапусти её. GSI принимает запросы локально на `127.0.0.1:43829` с собственным токеном. Предпочтителен режим игры без рамки. Путь текущей локальной установки автора: `D:\SteamLibrary\steamapps\common\dota 2 beta`; он **не является обязательным путём** для другого компьютера. Обнаружение установки проверяет реальные файлы игры, а не только оставшуюся папку `cfg`.

Для live-обновления STRATZ владелец должен **лично ввести собственный API-токен в настройках приложения**. Не проси отправлять его в чат. Не добавляй токен, его зашифрованную копию или GSI-токен в Git, примеры, логи и скриншоты. Electron использует Windows `safeStorage`; файл credentials не предназначен для переноса на чужой компьютер.

## Проверки и сборка

```powershell
pnpm test
& .\node_modules\electron\dist\electron.exe . --smoke-test
pnpm run package
```

Portable-сборка появляется в `release/Core Coach/Core Coach.exe`; её можно отдельно проверить с `--smoke-test`. `scripts/package-portable.cjs` переносит исходники и поставляемые данные, применяет Windows-метаданные и сохраняет существующее пользовательское состояние сборки. Запускай только одну версию одновременно: приложение использует single-instance lock и один порт GSI. Перед GUI smoke закрой обычный Core Coach, иначе второй запуск может только открыть уже работающее окно.

Smoke создаёт GUI, использует тестовые пакеты GSI, пишет отчёт `artifacts/smoke.json` и завершает приложение. При запуске из portable-папки путь отчёта находится внутри `resources/app/artifacts`. Для него нужен доступный графический сеанс Windows. В исходниках smoke читает настройки текущего экземпляра и восстанавливает их после проверки; для независимой проверки лучше использовать чистую копию без чужого `runtime`.

Ранее для версии 0.9.7 были получены **673/673 успешных теста** и **80/80 проверок packaged smoke**. Это исторический результат предыдущего этапа, **не утверждение о новом запуске тестов при подготовке этого документа**. Новому исполнителю нужно повторить подходящие проверки после своих изменений.

Дополнительные проверки по задаче:

```powershell
& .\node_modules\electron\dist\electron.exe test/vision-fixtures.cjs
pnpm run draft:sensitivity
node scripts/evaluate-draft.cjs --rank=HERALD_GUARDIAN
```

Проверка чувствительности использует статистические кеши выбранного рейтинга; без подходящих файлов возможна честная ошибка отсутствия данных. Она проверяет изменение рекомендаций, а не рост числа побед. Команды `data:update`, `draft:update` и скрипты обновлений выполняют сетевые запросы — они не нужны для обычного первого запуска уже поставляемых данных.

## Статистика: что уже есть и что нельзя обещать

- STRATZ — основной источник. Адаптер проверяет реально доступную GraphQL-схему, не считает неизвестный фильтр применённым и сохраняет прежний пригодный кеш при ошибке обновления.
- База WR и пары имеют отдельные контексты и проверки актуальности. Дата скачивания не заменяет дату наблюдений. Несовместимый патч, смешанные фильтры и слишком старые данные могут исключаться из оценки.
- Выбор рейтинга в UI — укрупнённые группы: Рекрут/Страж, Рыцарь/Герой, Легенда/Властелин, Божество/Титан либо все рейтинги. Это **не точный MMR и не отдельный дивизион внутри группы**. При отсутствии кеша выбранной группы общий кеш не выдаётся за неё.
- База может быть отфильтрована по позиции; используемый метод общих пар STRATZ не подтверждает позицию. При базе выбранной позиции общие пары получают коэффициент **0,25**. Этот коэффициент не следует незаметно менять в ходе UI-правок.
- Нативный эффект STRATZ не корректируется повторно. Для резервного расчёта учитывается общая сила обоих героев; старые эффекты, вычитавшие только WR кандидата, исключены. Малые выборки базы и пар сглаживаются.
- Внутренние масштабы вкладов врагов и союзников — 90 и 50. База тоже влияет; это не жёсткое правило «любой контрпик всегда выше сильного героя». Пока нет данных, позволяющих доказательно подобрать лучшие веса.
- Подтверждённая недельная граница пар не сообщает дату последнего фактического матча. Каталог версии STRATZ также не доказывает независимо патч установленного клиента. Не подменяй неизвестное текущим значением.
- Кандидат содержит полноту базы/пар, их периоды, ограничения и предупреждение о близких оценках. Уверенность и близость — эвристики интерфейса, не доверительный интервал или доказанное превосходство.
- OpenDota — резерв с явно указанными ограничениями. Предполагаемая позиция по линии и фарму не равна подтверждённой позиции. Отсутствующие данные не должны становиться фиктивным преимуществом или рекомендацией.
- Улучшение относительно простого сглаженного WR по позиции **ещё не доказано на исторических матчах**. Runner подготавливает и проверяет записи без утечки будущих данных; готового подтверждённого набора решений и исходов для вывода о точности нет. Он пока не вычисляет log loss/Brier для необоснованно трактуемого индекса.

Подробности: `PICKER-VALIDATION-0.9.3.md`, `DRAFT-EVALUATION.md`, тесты `draft-*`, `stratz.test.cjs`. Для текущего UI сверяйся с `src/draft-ui.js`, `src/draft-window.js` и `src/draft-coach.cjs`: сейчас рекомендуются до пяти героев, с простыми объяснениями. Старые changelog-файлы описывают исторические версии и не заменяют текущее поведение кода.

Распознавание участников линии остаётся чувствительным к HUD, масштабу, перекрытиям и достаточности повторных кадров. Сходство с шаблоном не является вероятностью правильного ответа. Ручное исправление состава — рабочий запасной путь, а не скрытая гарантия точного автоопределения. Нагрузка на FPS в разных матчах и конфигурациях ещё требует замеров; не добавляй постоянные тяжёлые запросы и обработку целого экрана без необходимости.

## Косметика: текущее состояние

В 0.9.7 старый скинченджер удалён из активного UI, запуска главного процесса и IPC. Старые `local-skins`, `local-cosmetics`, `local-terrain` и связанные helpers оставлены как **неактивный recovery-код**, а не новая рабочая функция. Не восстанавливай их запуск случайным импортом.

**Inventory changer не реализован.** Отдельный эксперимент с локальным файлом кеша не показал Arcana Drow Ranger в доступном инвентаре игры; экипировка не подтверждена. Эксперимент не входит в приложение. По журналу предыдущего этапа исходный кеш восстановлен с проверкой SHA-256. Экспериментальные файлы и локальные игровые данные не предназначены для публикации.

`src/native-set-preview.cjs` — отдельная **неподключённая и не подтверждённая игровым тестом** заготовка штатной примерки Sepulchral Stalker. Это не выдача предметов, не разблокировка владения и не подтверждение рабочего inventory changer. Историю удаления смотри в `CHANGES-0.9.7.md`.

## Что передаётся через Git, а что остаётся локально

В репозитории нужны исходники, тесты, скрипты, lockfile, документация и отобранные поставляемые данные/ресурсы. `data/d2pt-wraith-king.json` — историческое имя резервного файла **OpenDota**, не разрешённая выгрузка Dota2ProTracker; не переименовывай его происхождение в интерфейсе.

**Исключаются из Git и архива для передачи исходников:** `runtime/`, `artifacts/`, `node_modules/`, `release/`, логи, личные настройки, credentials, GSI-конфиги с секретами, резервные копии игровых файлов и локальные кеши аккаунта. Это относится и к вложенным `resources/app/runtime` внутри portable-сборки. Приватный GitHub не заменяет исключение секретов. Чужие Windows credentials нельзя переносить как готовый доступ к API.

В частности, папка `artifacts/` содержит исследовательские материалы и результаты локальных проверок; её отсутствие в клоне нормально. Генерируй новые отчёты локально. Нужный другому разработчику обезличенный fixture сначала отдельно проверь и включи в `test/fixtures` осознанно.

Установи зависимости из pnpm-lock.yaml, пройди подходящие тесты и, если доступен Windows GUI, smoke. Не читай и не публикуй runtime, токены и личные игровые кеши. Сохрани производительность, оверлеи и честное отображение ограничений данных. Не обещай доказанный рост точности, успешный live-запрос API или работающий inventory changer без соответствующей проверки. Сначала воспроизведи проблему, затем внеси минимальные обоснованные изменения и сообщи, что именно проверено, а что осталось неизвестным.
